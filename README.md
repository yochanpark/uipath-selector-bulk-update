# UiPath 셀렉터 일괄 수정

고객사 UiPath 프로세스에서 한꺼번에 깨진 셀렉터 수십 개를 `.xaml` 구조를 분석해 PowerShell로 일괄 교체한 작업이다.

> 회사 업무로 수행한 작업이라 프로젝트 파일·스크립트·셀렉터 원문은 올리지 않고, **어떤 일을 했는지만** 적었다.

| 개요 | |
|---|---|
| 기간 · 역할 | 2026.08 · 단독 수행(원인 파악 · 일괄 수정 · 복구 · 재배포) |
| 기술 | UiPath Studio · Orchestrator · PowerShell · XAML |

---

## 상황

디자인 프로그램(Adobe Illustrator)을 조작하는 프로세스가 클릭 단계에서 계속 실패했다.
프로그램 창 구조가 바뀌어 창 순서 번호가 고정된 셀렉터가 맞지 않게 된 것이 원인이었다.
같은 버튼을 누르는 Click 액티비티가 여러 워크플로우에 수십 개 흩어져 있어 Studio에서 하나씩 고치기엔 너무 많았다.

## 한 일

- **파일 저장 구조 분석**: Studio 편집기에 보이는 셀렉터와 `.xaml` 안에 저장된 형태가 다르다는 것(특수문자 이스케이프, 한 줄로 이어짐, 속성 순서 차이)을 파일 원문을 열어 확인했다. 처음 "0건 수정"이 나온 원인이 이것이었다.
- **교체 범위 좁히기**: 처음에는 해당 창의 셀렉터를 전부 바꿔 다른 버튼까지 바뀌었다. 이후 버튼 이름까지 포함한 원문 전체를 정확히 일치시키는 방식으로 바꿔, 요구된 버튼만 교체되게 했다.
- **셀렉터 안정화**: 문서 상태에 따라 바뀌는 창 제목 대신 변하지 않는 도구 패널 창을 기준점으로 삼고, 고정된 순서 번호를 없애 창 순서가 바뀌어도 맞게 했다.
- **스크립트 작성**: 정규식 특수문자가 많은 셀렉터 특성상 문자열 그대로 비교·치환하게 했고, 바뀐 파일 수를 출력해 0건이면 원문을 다시 보도록 했다. 사용자가 별도 도구 설치 없이 Studio·PowerShell 안에서 끝내길 원해 그에 맞췄다.
- **복구와 재배포**: 중간 시도에서 잘못 바뀐 파일은 손으로 되돌리지 않고 Orchestrator에 게시돼 있던 패키지에서 소스를 복원했다. 수정본은 버전을 올려 게시하고, 기존 프로세스의 패키지 버전만 교체했다.
- **부수 장애 분석**: 같은 시기 Studio 저장 실패(OutOfMemoryException)를 스택 추적으로 분석해, 실제 메모리 부족이 아니라 백그라운드 서비스의 큰 문자열 처리 문제로 판단했다.

## 결과

- 수십 개 액티비티를 Studio에서 하나씩 열지 않고 한 번에 정확히 교체했다.
- 창 상태가 바뀌어도 깨지지 않는 셀렉터로 바꿔 재발을 줄였다.
